# A 组专家评估与优化

这是共同评测合同的起步 Skill，不代表 Promptfoo、OpenCode Provider、本地 Web 或具体优化逻辑已经实现。
实际执行前必须检查本插件是否已经提供相应配置、脚本和依赖；缺失时列出缺口，不得伪造运行结果。

## 不可变规则

- 原始专家包始终只读。任何优化都写入带版本标识的新副本。
- 每轮同时记录 case、模型、专家版本、运行环境、配置和输入哈希。
- 优化前后必须使用相同 case、模型、采样参数和运行环境。
- 截图和口头说明不能代替原始输出、结构化指标、运行日志和可复现命令。
- 静态检查、配置解析或插件安装不能描述为真实 OpenCode/Promptfoo 业务链路已通过。

## 标准流程

1. 确认评测对象、任务类型、基线版本、模型矩阵、评分指标和成功阈值。
2. 为结构化、混合式和开放式任务准备可版本化 case，并校验输入完整性。
3. 记录运行清单，执行原始版本以及“使用专家／不使用专家”的基线评测。
4. 从失败 case 和证据定位问题；保留原包，生成带版本标识的优化副本。
5. 在相同条件下复测，并比较不同模型、原始版本和优化版本。
6. 输出本地 Web 报告及机器可读结果，列出改进、退化、失败和未验证项。

## 最低输出

- 评测对象与版本
- case 清单与分类
- 模型和运行环境
- 原始输出与结构化指标
- 优化变更及新副本标识
- 优化前后对比
- 复现命令
- 已验证、失败和待验证边界
