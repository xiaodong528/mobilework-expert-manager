# MobileWork 专家管理器领域上下文

本文只定义稳定业务概念及其边界，不描述脚本、函数或文件实现。

## 核心概念

### 专家包

可被校验、安装和调用的一个单专家或专家团交付单元。专家包拥有角色、能力资源、流程说明与运行
投影；其中 `expert.json` 是角色及资源归属的真源。

### 角色

承担明确职责、拥有明确资源并以独立 Agent 身份运行的参与者。单专家有一个角色；专家团有一名
团长和一名或多名团员。每个角色必须独立选择自主度，不从团队、Workflow 或 Phase 继承权限档位。

### 角色自主度

角色可执行静态动作的唯一权限基线。用户使用低、较低、中、较高、高五个标签选择，真源内部保存
为 `scripted`、`fixed`、`bounded`、`guided`、`adaptive`。角色自主度回答“这个角色最多可以做
什么”，不回答某个流程步骤应由谁决定。

### 流程自主度

Workflow、Phase 或角色流程覆盖中描述决策范围、确认点、风险与验收责任的流程属性。它回答“这个
步骤怎样推进”，不能新增资源所有权、生成权限白名单或提升角色权限。

### 资源所有权

角色被明确分配的 Skill、MCP、custom tool 和团队委派关系。所有权回答“这个能力属于谁”；角色
自主度回答“所有者能以何种动作使用它”。未声明的 MCP 或 custom tool 不因高自主度而成为角色
能力。

### 业务能力候选

管理器从用户目标、角色职责、流程、质量要求或可信资料中识别的可固化能力。候选必须有稳定业务
名称、可观察运行行为和可追溯来源。角色存在、职责条目、流程步骤或质量门本身不直接生成资源；
管理器可以提出候选，但不能发明业务规则、阈值、外部读写或运行副作用。

### 能力实现映射

在完整业务卡确认后，管理器按最小运行权限把不同职责分别映射为无资源、Skill、Custom Tool 或
OpenCode Plugin。可复用方法、清单、SOP、指导材料以及随包封装的 Python/Shell 脚本适合 Skill；
角色主动调用的确定性 JavaScript/TypeScript 能力适合 Custom Tool；事件监听、工具执行前后拦截和
运行时行为修改适合 Plugin。访问外部系统继续使用 MCP，不以 Plugin 冒充连接器。

同一运行职责只创建一个资源；不同且已确认的职责可以组合资源。同一能力只创建一份，多个角色
通过完整名称或所有权共享。业务 Skill 使用语义名称，不强制专家或角色前缀；Custom Tool 与本地
Plugin 保留包命名空间，Plugin 是 package-wide 运行行为，不属于单一角色。

### 权限动作

对某项能力的静态决策：`allow` 表示可直接执行，`ask` 表示执行前确认，`deny` 表示不可执行。
角色手写权限只能把动作收紧，不能超过角色自主度基线。

### 已分配 Skill

专家包内存在且显式绑定到角色的 Skill。它属于角色交付能力，五档角色自主度下均被精确允许。

### 外部 Skill

宿主可发现但未分配进专家包的 Skill。低、较低、中角色不可加载；较高角色加载前确认；高角色可
直接加载。这个跨包发现能力是 Skill 所有权规则的明确例外，不会同时开放未声明的 MCP 或 custom
tool。

### 上传 Skill

由用户提供、准备绑定到目标角色的外部 Skill 包。只有同时通过官方 Agent Skills 格式和 MobileWork
安全、归档、便携性门禁后，才成为包内已分配 Skill；通过的内容保持目录树和文件字节不变，失败时
专家包保持原状态。

### 生成授权

完整业务卡的确认只授权当前专家包内已确认能力资源的生成。它不授权安装、启用、联网下载、外部
连接、权限扩大、执行生成代码或发布。管理器发现新的自动触发、外写、联网、权限、依赖、成本或
Runtime 前提时，旧确认失效；重新完整确认前保持零写入。生成后的业务 Agent 在普通运行中只消费
既有专家包，不自行修改资源映射或专家包。

### 结构性修改

改变角色、角色自主度、能力池、角色能力分配、Workflow、权限或运行身份的修改。结构性修改前，
所有角色必须已有显式自主度；旧主 Agent 身份也在此时迁移到当前模式。

### 兼容临时投影

旧包缺少角色自主度时，为只读诊断、校验和安装临时使用“中”生成权限。临时投影不回写真源；它
以 warning 暴露兼容状态，不能作为继续结构性修改的隐式选择。

## 身份与流程模式

新建单专家主 Agent 和专家团团长使用 `all`，既可直接使用，也可被通用 Agent 调用；团员使用
`subagent`。Workflow Phase 的 `primary` 只表示该 Phase 的流程参与方式，与 Agent 身份模式不是同一
维度。旧主 Agent 的 `primary` 可继续只读校验和安装，但结构性修改后迁移为 `all`。

## 关键不变量

- 固定角色自主度和资源所有权时，改变 Workflow/Phase 自主度或 execution 不改变静态权限。
- 固定流程时，改变角色自主度只产生五档矩阵规定的权限差异。
- execution 只能引用角色已经拥有且当前动作不是 `deny` 的能力。
- 角色数量、职责、流程和质量门不直接投影成 Skill、Custom Tool 或 Plugin。
- 能力实现映射优先选择最小运行权限；同一运行职责不得重复生成多个资源。
- Plugin 属于 package-wide 运行行为；角色所有权只适用于显式分配的资源。
- 能力实现映射不得超出当前完整业务卡；出现新 material impact 时先使确认失效并保持零写入。
- `permission_reason` 可以解释收紧，不能授权提权。
- 角色自主度只存在于真源；Agent Markdown 只接收其官方 `permission` 投影。
- 校验、安装、静态评测和配置读回不等于真实 MobileWork Electron 或 OpenCode 会话运行证据。
